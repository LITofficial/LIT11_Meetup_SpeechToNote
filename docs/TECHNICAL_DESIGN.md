# 데모 기술 설계

> 최신 상태 (2026-11-09): 사용자 후속 요청으로 강의노트 구현이 승인되어 세 종류 생성·키 설정·취소·PDF 기능을 구현했다. 외부 API 실호출과 사용자 무료 프로젝트/노트 품질 검증은 아직 미실행이다. 기존 전사 기능은 유지한다. 아래의 설계만 승인/미구현 표현은 이전 단계 기록이며 현재 상태는 IMPLEMENTATION_STATUS.md의 마지막 항목을 따른다.


## 구성

기존 Python + FastAPI + 기본 HTML/CSS/JavaScript 골격을 재사용합니다. 현재 가상환경은 Python 3.10.5이며 faster-whisper 1.2.1·CTranslate2 4.8.5의 실제 동작을 확인했습니다. UI 프레임워크 교체는 필수가 아닙니다.

faster-whisper의 CPU int8로 다국어 base·small 후보를 연결합니다. 한국어 인식과 원문 전사를 사용하고 번역·생성형 후처리·용어 강제 치환은 넣지 않습니다. 영어 전용 .en 모델은 제외합니다. 후보 엔진 근거는 [공식 저장소](https://github.com/SYSTRAN/faster-whisper)이며, 이 PC에서의 성능은 별도 측정해야 합니다.

## 처리 흐름

사용자가 파일 한 개와 모델 ID를 선택합니다. 서버는 고정 허용 목록에서 모델 ID를 찾고 로컬 파일 존재를 확인합니다. 임의 경로·모델 URL을 클라이언트로부터 받지 않습니다.

파일은 UUID 임시 디렉터리에 저장해 형식·크기·음성 유효성을 확인합니다. 별도 probe 프로세스가 실제 프레임을 디코딩합니다. 추론은 자식 프로세스에서 실행해 서버 응답을 유지합니다. 한 프로세스만 실행하고 새 작업은 진행 중일 때 거절합니다.

자식 프로세스는 선택한 모델을 로컬 경로로 읽습니다. 자동 다운로드를 하지 않습니다. 완료된 segment.text를 원래 순서대로 결합합니다. 모델 교체 시 이전 모델을 해제해 메모리가 누적되지 않도록 합니다.

결과를 메모리에 보관하고 화면과 다운로드에 같은 문자열을 사용합니다. 영속 SQLite·청크 트랜잭션·복구 fingerprint는 데모에 필요하지 않습니다. 결과를 읽거나 내려받은 뒤에도 명시적 새 작업 또는 만료까지 재다운로드할 수 있습니다.

## 자원 수명

설계 기본 업로드 상한은 200MiB입니다. 사용량 크레딧이 아닌 데모 자원 보호값이며 파일 선택 전에 안내합니다. 시연 파일은 1~5분 권장입니다. 장시간 파일 지원을 약속하지 않습니다.

종료·실패·작업 완료 때 업로드 임시 음성을 정리합니다. 원본 파일은 변경하지 않습니다. 완료 결과는 최대 30분 또는 다음 작업 시작까지 유지합니다. 진행 작업은 30분 경과를 이유로 조용히 삭제하지 않습니다. 서버 종료 시 자식 프로세스를 종료하고 임시 파일을 정리합니다. 비정상 종료 잔여물은 다음 실행에서 관리 임시 폴더만 청소합니다.

## 모델 준비

모델 설치는 별도 준비 명령으로 수행하고 시연 전에 base·small을 모두 내려받아 확인합니다. 음성 전사 요청에는 외부 다운로드를 섞지 않습니다. prepare-models.cmd를 사용하며 실제 설치 버전은 requirements.lock, 모델 revision·SHA-256은 각 models/<id>/manifest.json에 기록합니다. 추론 시 모델 파일 존재와 크기를 검사합니다.

녹음·전사문·로그의 외부 전송, Gemini SDK·키 저장·AI 전송 승인은 구현하지 않습니다.

## Turbo·선택 힌트 추가 (2026-11-08)

사용자 요청으로 large-v3-turbo 모델 선택과 최대 100자의 선택 힌트를 추가했습니다. 힌트는 입력 문구를 initial_prompt로 그대로 전달하며 빈 입력도 허용합니다. 자동 교정·외부 API는 추가하지 않습니다. 처리 중 입력을 잠그고 힌트 변경 시 기존 결과·다운로드를 초기화합니다. 시간보다 품질을 우선한다는 최신 결정을 반영하며 3분 이내 완료를 보장하지 않습니다.

## 문장 단위 표시 (2026-11-08)

모델의 음성 구간 경계는 공백으로 연결하고 마침표·물음표·느낌표 등 문장 종료 부호 뒤에 빈 줄을 둡니다. 소수점·버전 번호·도메인과 대표 영어 약어는 보수적으로 처리합니다. 공백과 줄바꿈만 변경하며 단어 교정, 문장부호 삽입, 요약은 하지 않습니다. 문장부호가 누락된 발언은 길게 이어질 수 있으며 모든 약어/문장 경계를 완벽히 판별하지는 않습니다.

worker에서 한 번 정리한 같은 text를 화면과 Markdown 다운로드에 사용합니다. Markdown 문법 이스케이프는 기존과 동일하며 문장별 구분은 유지합니다. 재전사는 필요 없지만 이미 실행 중인 앱/기존 결과는 자동 변경하지 않습니다. 앱 재시작 후 새로 전사한 결과에 적용됩니다.

## 로컬 전사 진단

사용자 요청으로 구간별 반복·낮은 신뢰도·음성 길이 초과를 기록합니다. 전사문과 다운로드 내용은 변경하지 않으며 자동 삭제·교정·재전사는 하지 않습니다.

기본 저장 위치는 `%LOCALAPPDATA%/LectureTranscriber/diagnostics/<작업 UUID>.json`입니다. 별도 --data-dir 실행은 해당 폴더의 diagnostics에 저장합니다. 종료 후에도 보존하며 자동 삭제하지 않습니다. 불필요한 기록은 사용자가 직접 삭제할 수 있습니다. 장시간 사용하면 기록 파일이 누적됩니다.

저장 항목: 모델 ID, 힌트 유무, 음성 길이, UTC 시작 시각, 구간별 시간·평균 log probability·compression ratio·no-speech probability·temperature·문자 수·연속 반복 횟수·감지 사유. 음성·파일명·개인 경로·힌트 내용·전사문은 기록하지 않고 외부 전송도 하지 않습니다.

기준은 탐색적 기본값입니다: avg_logprob < -1.0, compression_ratio > 2.4 또는 최대 4토큰 문구의 4회 이상 연속 반복(직전 24토큰 포함), 종료 시각 > 실제 음성 길이+1초 또는 음수/역전 시간. 정상 강조도 감지될 수 있으므로 오류 확정 판정이 아닙니다. 모든 반복과 누락을 검출하는 기능은 아닙니다.

각 구간마다 .partial 파일 작성 후 원자 교체합니다. 기록 상태는 running/completed/failed입니다. 강제 종료 시 running 기록이 남을 수 있으며 모델 로딩 전에 실패하면 기록이 없을 수 있습니다. 진단 저장 실패는 전사 완료를 막지 않고 화면에 알립니다. 진단 경로는 브라우저 API에 노출하지 않습니다.

## 힌트 대체 구간 자동 재전사

사용자 요청으로 입력 힌트만 출력하는 10초 이상 구간을 감지하여 힌트 없이 한 번 재전사합니다. 공백·문장부호·대소문자를 정규화한 힌트 전체의 동일/반복 출력만 대상으로 하며 모든 누락을 감지하지는 않습니다. 인접한 의심 구간을 합치고 앞뒤 최대 5초 범위에 완전히 들어오는 기존 구간을 함께 처리합니다. 경계 밖의 원래 구간은 그대로 보존합니다.

재시도에는 initial_prompt=None, condition_on_previous_text=False를 사용하고 나머지 기본 전사 조건은 유지합니다. 작업당 최대 3개 영역, 영역당 최대 180초, 영역별 1회로 제한합니다. 한도를 넘거나 실패하면 원래 내용을 유지합니다. 빈 결과·힌트 반복·연속 반복·평균 로그 확률 -1 미만·압축비 2.4 초과·구간 시간 초과는 자동 반영하지 않습니다. 이 검사는 정확도 보장이 아니며 반영된 결과도 사용자가 확인해야 합니다.

일반 diagnostics는 계속 수치만 기록합니다. 별도 **recovery/<작업 UUID>.json에는 원래 전체 전사문과 구간, 각 재시도의 원래/새 텍스트 및 시간, 최종 전사문, 반영 여부를 보존**합니다. 이는 사용자가 승인한 로컬 복구 기록이며 민감한 강의 내용이 포함될 수 있습니다. 외부 전송·Git 추가·자동 삭제는 하지 않습니다. 기본 위치는 %LOCALAPPDATA%/LectureTranscriber/recovery, --data-dir 실행은 해당 데이터 폴더 아래입니다. 사용자가 필요에 따라 직접 관리합니다.

원래 전사문은 재시도 전에 원자 저장하고 재시도 부분 결과도 순차 저장합니다. 저장 실패 시 새로운 결과를 적용하지 않습니다. 강제 종료 시 pending/부분 기록이 남을 수 있으며 자동 복구 재개는 제공하지 않습니다. 작업이 끝나면 화면에 반영/확인 필요/저장 실패 상태와 원래 전사문·재전사 기록 다운로드를 표시합니다. 일반 Markdown 다운로드와 화면에는 같은 최종 전사문을 사용합니다. 다운로드 링크는 현재 작업 수명에 따르며 파일은 종료 후에도 로컬에 남습니다.

## 일반 단어·구절 반복 복구 확장

이전의 힌트 전용 대상 및 작업당 3곳 제한을 대체합니다. 힌트 유무와 관계없이 대소문자·문장부호를 정규화한 1~8토큰 단어/구절이 4회 이상 연속 반복되는 실제 텍스트 범위를 찾습니다. 구간 경계를 넘는 반복도 탐지하고, 중첩 후보는 합치며, 반복 뒤 이어지는 낮은 신뢰도 구간도 포함합니다. 정상적인 두세 번 강조나 서로 떨어진 같은 단어는 이 규칙으로 자동 삭제하지 않습니다. 네 번 이상의 실제 발언도 재전사 대상이 될 수 있으며 완전한 오탐 방지를 보장하지 않습니다.

발견된 모든 영역을 순차 처리합니다. 각각 최대 180초 범위에서 1회 재전사하며 긴 반복은 기존 세그먼트 경계로 분할합니다. 단일 세그먼트 자체가 180초를 넘거나 시간이 잘못된 경우는 확인 필요로 남깁니다. 재시도에 반복/낮은 신뢰도/시간 초과가 남으면 원래 결과를 유지합니다. 단순 문자열 삭제·강제 용어 치환은 하지 않습니다.

화면은 반복·누락 의심 구간의 반영/미해결 수를 표시합니다. 원래/재시도/최종 기록과 각 시도의 reasons(repetition/hint_only)는 로컬 recovery JSON에 보존됩니다. 일반 Markdown 다운로드는 적용된 최종 문자열을 사용합니다. 무제한 재시도는 하지 않지만 영역이 많으면 시간이 더 걸립니다. 같은 단어의 모든 변형/비연속 반복을 잡거나 모든 반복을 성공적으로 복구하는 보장은 없습니다.


## 연속 저신뢰도 자동 복구 추가 (2026-11-08)

사용자 승인에 따라 avg_logprob < -1인 구간이 2개 이상 연속되고 전체 길이가 10초 이상이면 독립적인 재전사 대상으로 추가합니다. 유효한 시간·유한한 점수가 필요하며 구간 사이 간격은 0~1초여야 합니다. 이는 보수적인 탐색 기준이며 정확도 확률이 아닙니다. 단일 저신뢰도 구간은 이번 규칙의 대상이 아닙니다.

기존 앞뒤 최대 5초 문맥 확장, 중첩 병합, 최대 180초 분할 및 영역별 1회 재시도를 재사용합니다. 최초 전사에는 사용자 힌트를 유지하며 재시도만 힌트 없이 이전 텍스트 참조를 끕니다. 기존 품질 검사 실패 시 원문을 유지합니다. 원래/재시도/최종 결과를 보존하고 recovery.attempts[].reasons에 low_confidence를 추가합니다. API 구조와 일반 수치 진단은 유지합니다. 복구 수치는 선택된 영역에 대한 값이며 전체 오류 해결을 의미하지 않습니다.

## 강의노트 기술 추가안 (설계만 승인)

최종 구간 스냅샷, 어댑터·키 관리·작업 상태·로컬 PDF는 [기술 설계](STUDY_NOTES_TECHNICAL.md)를 따른다. 현행 worker가 최종 문자열만 반환하므로 근거 시간 연결은 선행 구현/검증 대상이다.
